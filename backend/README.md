# Сервер записи ÉCLAT STUDIO (Google Apps Script + Google Sheets)

«Мозг» онлайн-записи: база записей в Google Sheets, серверная проверка свободных
окон, защита от двойного бронирования, пенсионная скидка и письма владельцу.
Бесплатно, на вашем аккаунте Google.

Файл: **`backend/appsscript.gs`** (версия 2.5 — чистая клиентская труба).

---

## Что умеет

| Действие | Кто зовёт | Токен | Что делает |
|---|---|---|---|
| `ping` | все | — | «я живой», время, версия |
| `test` | админка, вы | — | диагностика: записей всего/сегодня/отменено, прочитан ли каталог сайта, задан ли токен |
| `busy` | сайт | — | занятые окна за период — то, что нужно движку расписания |
| `book` | сайт | — | создать запись (полная серверная проверка + письмо владельцу) |
| `getStats` | админка | ✅ | счётчики и сумма активных записей |
| `getDay` | админка | ✅ | записи и блоки конкретного дня |
| `list` | админка | ✅ | записи за период |
| `cancel` | админка | ✅ | отменить запись (строка остаётся, статус «отменена») |
| `addBlock` | админка | ✅ | заблокировать интервал (обед, ремонт, съёмка) |
| `unblock` | админка | ✅ | убрать блок |
| `manualBook` | админка | ✅ | запись «клиент позвонил» (без письма владельцу) |
| `lead` | сайт (чат-ассистент) | — | заявка из чата: лист «Заявки из чата» + письмо |
| `tidy` | вы | ✅ | привести **все** таблицы в порядок (ширины, русские шапки, оформление, удаление пустых колонок и вкладок) |
| `reload` | вы | ✅ | сбросить кеш каталога (после правки цен) |

Примеры:

```
URL/exec?action=test
URL/exec?action=busy&from=2026-10-22&to=2026-12-21
URL/exec?action=book&data={"serviceId":"w1","masterId":"m1","date":"2026-10-25","startMin":600,"name":"Анна","phone":"+79310001122","consent":true}
URL/exec?action=getDay&date=2026-10-25&token=ВАШ_ТОКЕН
```

Все ответы — JSON, а при `&cb=имя` — JSONP (`имя({...})`), чтобы сайт мог
читать их из браузера без CORS.

## Контракт с сайтом (важно!)

Сайт (`js/app.js`) говорит на «машинном» языке движка расписания:

```js
{ serviceId: 'w1', masterId: 'm1', date: '2026-10-25', startMin: 600,
  name, phone, comment, pension: true, consent: true, minutes: 60 }
```

и **заворачивает это в один параметр `data=JSON`**. Сервер обязан:

1. распарсить `data`,
2. по `serviceId`/`masterId` найти услугу и мастера в `site-data.js`,
3. посчитать цену и скидку **сам** (браузеру не верим),
4. вернуть запись в обоих языках — и машинном (`startMin`, `masterId`, `status: 'confirmed'`),
   и человеческом (`start`, `master`, `statusRu: 'подтверждена'`).

Ответ `book`:

```json
{ "ok": true, "id": "ECL-0001", "mailSent": true,
  "booking": { "id":"ECL-0001","masterId":"m1","serviceId":"w1","date":"2026-10-25",
               "startMin":600,"endMin":660,"start":"10:00","end":"11:00",
               "master":"Алиса","service":"Женская стрижка","status":"confirmed",
               "name":"Анна","phone":"+7 931 000-11-22","price":1350,"priceBase":2700,
               "discountPercent":50,"source":"сайт" } }
```

Отказ из-за занятого времени обязательно содержит `"reason": "conflict"` —
по нему сайт возвращает клиента на шаг выбора времени и перечитывает расписание.

## Установка (10 минут)

1. Откройте https://script.google.com → «Новый проект».
2. Удалите содержимое `Code.gs` и вставьте **всё** из `backend/appsscript.gs`.
3. В шапке скрипта поправьте три строки:
   - `OWNER_EMAIL` — почта, куда приходят заявки;
   - `ADMIN_TOKEN` — придумайте случайную строку (например `eclat-7f3k9x2q`).
     **Именно её** вы будете вводить в админке. Пока там плейсхолдер
     `ВСТАВЬТЕ_СВОЙ_ТОКЕН`, админ-действия запрещены — так задумано;
   - `SITE_DATA_URL` — адрес опубликованного `site-data.js`
     (по умолчанию уже ваш: `https://venera0207.github.io/eclat-studio/site-data.js`);
   - `TZ` — часовой пояс салона (`Europe/Moscow`). От него зависит «сегодня»
     и проверка «это время уже прошло».
4. Сохраните проект (имя: «ÉCLAT bookings»).
5. «Развернуть» → «Новое развертывание» → тип **«Веб-приложение»**:
   - «Выполнять как»: **я**;
   - «Доступ»: **все**.
6. Скопируйте URL (оканчивается на `/exec`).
7. Если URL новый — впишите его в `site-data.js` → `SETTINGS.pipeUrl`
   (удобнее через `redaktor.html`, вкладка «Настройки») и закоммитьте.
   Админка берёт адрес трубы **из того же `site-data.js`** — второй раз вшивать не нужно.
8. Проверка в браузере:
   - `URL/exec?action=test` → `{"ok":true,...,"services":25,"masters":4,"catalogOk":true}`
   - `URL/exec?action=ping` → `{"ok":true,...}`

### Важно про повторное развертывание
Apps Script не обновляет `/exec`-адрес автоматически. После каждой правки кода:
**«Развернуть» → «Управлять развертыванием» → ✏️ → «Версия: Новая версия» → «Развернуть»**.
URL при этом остаётся прежним — сайт и админку трогать не нужно.

## Таблицы

При первом обращении скрипт сам создаёт таблицу
**«ÉCLAT STUDIO — база записей»** (её id запоминается в свойствах скрипта как `DB_ID`)
и три листа:

- **Записи** — `Номер, Дата, Начало, Конец, Мастер, Услуга, Имя, Телефон, Комментарий,
  Статус, Цена, Скидка, Источник, Создана, МастерID, УслугаID, НачалоМин, КонецМин, ЦенаБаза, Пенсионер`
- **Блоки** — `ID, Дата, Начало, Конец, МастерID, Мастер, НачалоМин, КонецМин, Причина, Создан`
- **Журнал** — `Время, Событие, ID записи, Подробности`

Первые 14 колонок «Записей» — человекочитаемые, их удобно смотреть глазами.
Последние 6 — машинные: по ним сайт строит расписание, поэтому **порядок колонок
не менять**.

### Почему часть колонок помечается текстовыми

Google Sheets сам «угадывает» тип значения, и это портит данные:

| Что пишем | Что делает Sheets | Чем лечится |
|---|---|---|
| `+7 931 357-96-00` | плюс в начале = формула → **`#ERROR!`** | формат `@` (текст) |
| `17:00` | превращает в значение времени; при чтении возвращается Date с **1899** годом | формат `@` + чтение через `minutesOf()` |
| `2026-10-22 11:15` | превращает в дату; в ответе уезжает «Thu Oct 22 2026 …» | формат `@` + `str()` понимает Date |

Поэтому сервер вызывает `appendRowText()`, который делает **два прохода**:
1. помечает текстовые колонки (`BOOK_TEXT_COLS`, `BLOCK_TEXT_COLS`, `LOG_TEXT_COLS`) форматом `@`;
2. пишет строку через `appendRow`;
3. **перезаписывает** текстовые ячейки через `setNumberFormat('@').setValue(...)`.

Шаг 3 обязателен: на бою выяснилось, что одного лишь шага 1 мало — `appendRow`
всё равно отдаёт значение парсеру Sheets, и телефон становился `#ERROR!`
даже при заранее выставленном текстовом формате (версия 2.1). Второй проход
гарантированно кладёт дословный текст.

При чтении сервер всё равно страхован: `minutesOf()`, `cellMinutes()`, `ds()` и `str()`
умеют разбирать и строки, и Date-ячейки — старые строки читаются корректно.

Диагностика испорченных строк: `URL/exec?action=test` вернёт
`"brokenRows": 2, "brokenIds": ["ECL-001 (телефон, время)"]` — такие строки
лучше удалить в таблице вручную, телефон из `#ERROR!` не восстановить.

Если хотите свою таблицу — создайте её, скопируйте id из адреса
(`/spreadsheets/d/<ЭТОТ_ID>/edit`) и в редакторе скрипта выполните:

```js
PropertiesService.getScriptProperties().setProperty('DB_ID', 'ВАШ_ID');
```

## Проверки, которые сервер делает сам

Даже если сайт «подделает» данные, сервер откажет:

- услуга/мастер существуют, активны и мастер выполняет эту услугу;
- дата не в прошлом, время сегодня ещё не наступило;
- мастер работает в этот день (дни недели, отпуск), время в пределах его часов;
- интервал не пересекается с перерывом мастера;
- интервал не пересекается с чужой записью **с учётом буфера** (`SETTINGS.bufferMin`, у вас 10 мин)
  и с блоками (`all` — для всех мастеров);
- имя ≥ 2 символов, телефон ≥ 10 цифр, есть согласие на обработку данных;
- цена и скидка считаются из `site-data.js`, а не из того, что прислал браузер;
- всё это под `LockService` — два одновременных запроса на одно окно не пройдут оба.

В редакторе скрипта один раз выполните `installReminderTrigger` (потребуются
разрешения на почту). Дальше в 19:00 по `TZ` вам будет приходить список записей
на завтра. Отключить — `removeTriggers`.

Сервер написан так, что его можно гонять локально, без Google:


`site-data.js` читается с диска) и прогоняет настоящий `backend/appsscript.gs`.

## Заметки

- Каталог сайта кешируется 5 минут: поменяли цену в редакторе — сервер узнает сам.
  Нужно мгновенно: `URL/exec?action=reload&token=ВАШ_ТОКЕН`.
- Письмо владельцу отправляется **после** сохранения записи: если почта не ответит,
  запись не потеряется, а в «Журнале» появится пометка.
- Сайт без `pipeUrl` работает в демо-режиме: записи в localStorage посетителя
  и резервное письмо через FormSubmit.
- Отдельный скрипт `backend/eclat-pipe.gs` — это ИИ-ассистент салона (чат, заявки,
  Telegram). Он не связан с записью и подключается через `SETTINGS.assistantUrl`.
- **Это чистый клиентский файл.** Его можно копировать целиком для нового салона
  (парикмахерская, барбершоп, ногтевая студия): внутри нет ни бота заявок Венеры,
  ни «головы» ИИ для продаж, ни ссылок на её таблицы — только запись клиентов.

## Бот заявок и «голова» ИИ — БОЛЬШЕ НЕ ЗДЕСЬ (версия 2.5)

Версии 2.3–2.4 содержали Telegram-бота заявок для услуги «сайты для салонов»
и «голову» ИИ на ключ Z.ai. Это **личный инструмент Венеры**, а не часть салона,
поэтому весь этот код вынесен в отдельный проект:

* репозиторий: **`venera-sales`** → файл `leadpipe.gs`;
* проект Google Apps Script: **«Венера — продажи»**;
* своя таблица **«Венера — продажи»** (листы «Заявки», «Переписка с ботом», «Журнал»);
* свой бот **@venera_sites_02_bot**, свой вебхук, свой лендинг
  https://venera0207.github.io/venera-sales/ (старый адрес `…/eclat-studio/uslugi/`
  остался заглушкой-перенаправлением).

Что это даёт: труба салона остаётся чистой — её можно отдавать клиенту и
копировать для следующего салона, не вычищая из неё чужой код. Если Telegram
всё же пришлёт обновление бота на этот адрес, труба вежливо откажет
(`telegram webhook moved to venera-sales`) и ничего не испортит.

## Красивые таблицы

Таблицы приводятся в порядок **сами**, при каждой записи и по команде `tidyAll`
(`?action=tidy&token=…`). Что делает `beautify(sh, widths, wrapCols, dateCols)`:

1. ширина колонок — по содержанию; **лишние пустые колонки справа удаляются**;
2. пустой хвост строк снизу подрезается (таблица «по размеру»);
3. шапка — **по-русски**, жирная, белым по фирменному фиолетовому `#4C2E9E`,
   закреплена (`setFrozenRows(1)`);
4. длинные тексты — с переносом (`setWrap`) и выравниванием вверх, колонки
   диалогов 560–640 px: **текст не обрезается границей колонки**;
5. высота строк подбирается по содержимому (`autoResizeRows`);
6. чётные строки — светло-сиреневые `#F6F3FC`, новую заявку видно сразу;
7. пустая вкладка «Sheet1», которая остаётся при создании таблицы, удаляется
   (`dropEmptyTabs`), а первый лист новой таблицы просто переименовывается.

Полнота текста: диалоги и комментарии пишутся **целиком** — до 40 000 знаков
в ячейке (лимит Google 50 000). Если диалог длиннее видимой высоты строки,
в ячейке он всё равно лежит полностью: потяните нижнюю границу строки вниз.

Листы и ширины:

| Таблица | Лист | Заголовки |
|---|---|---|
| записи салона | `Записи` | Номер · Дата · Начало · Конец · Мастер · Услуга · Имя · Телефон · Комментарий · Статус · Цена · Скидка · Источник · Создана · … |
| блокировки | `Блоки` | ID · Дата · Начало · Конец · МастерID · Мастер · … · Причина · Создан |
| журнал | `Журнал` | Время · Событие · ID записи · Подробности |
| заявки из чата | `Заявки из чата` | Дата · Имя · Контакт · **Диалог** · Источник |

Труба ассистента (`eclat-pipe.gs`, v2.2) приводит в порядок свои листы так же:
`Заявки` (Дата · Имя · Контакт · **Заявка (весь диалог)** · Источник) и
`Диалоги` (Дата · **Код диалога** · Страница · Контакт · **Весь диалог** · Итог) —
заголовок `SID` заменён на русский, старые шапки чинятся сами (`ensureHead`).
