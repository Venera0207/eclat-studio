## Что работает и доказано
1. **Труба записей** (`backend/appsscript.gs`, v2.2, проект Google «ÉCLAT bookings»,
   exec-адрес в `site-data.js` → `SETTINGS.pipeUrl`):
   принимает `book` c `data=JSON`, отдаёт `busy`, пишет в таблицу «Записи» текстом
   (телефоны не ломаются), считает цену/скидку на сервере, защищает от двойного
   бронирования (LockService), шлёт письмо владельцу. Админка и сайт работают.
   Проверено: 43 теста стенда + боевые записи ECL-0001…0004 + письма.
2. **Труба ассистента** (`backend/eclat-pipe.gs`, v2, проект «ÉCLAT assistant»):
   `test` отвечает всеми флагами true; `lead` сохраняет в лист «Заявки»,
   шлёт Telegram и письмо MailApp — **доказано боевыми диагностическими заявками**
   (строки таблицы, сообщения робота, письма «ÉCLAT: заявка из чата — …»).
   `chat` отвечает через GLM (Z.ai) с промптом из живого site-data.js.
3. **Окошко чата** (`js/assistant-eclat.js`, на сайте v18): мгновенные ответы из базы,
   живые окна, приём имени/телефона в любом порядке, очередь заявок в localStorage,
   повторы 2,5 с / 9 с, журнал с задержкой 6 с, резервное письмо FormSubmit
   (не активирован и более не нужен — MailApp работает).

## Единственное ненадёжное звено (замерено, не догадка)
Доставка `lead` **из браузера** в exec-адрес трубы ассистента через JSONP-GET.
Замеры с сервера 22.10: серия из 4 запросов `lead` подряд → 4×HTTP 400 (HTML-страница
Google), одиночный запрос через минуту → HTTP 200 ok. То есть Apps Script фронтенд
отбрасывает пачки GET-запросов. Клиентские заявки в моменты пачек не доходили;
в таблице видны только диагностические заявки, отправленные одиночно.

## Рекомендованные технические решения (для следующего исполнителя)
1. **Перевести lead/chat/log с JSONP-GET на POST fetch** (Apps Script doPost) —
   POST не попадает под наблюдаемое ограничение пачек GET; ответ читать не обязано
   (достаточно факта доставки + локальной очереди).
2. **Дублировать lead в трубу записей** (она стабильна): добавить туда публичное
   действие `lead` (лист «Заявки из чата») и слать туда параллельно — заявка не
   зависит от капризов одной трубы.
3. Либо **вынести приём заявок из Apps Script** в стабильный внешний endpoint
   (любой серверless-провайдер с очередью и ретраями), оставив Apps Script только
   для таблицы/почты/Telegram.
4. Кеширование: все файлы сайта версионируются `?v=N`; после любой замены обязателен
   hard reload. GitHub Pages пересобирается 1–5 минут.
